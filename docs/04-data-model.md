# Data model

Notes live in Cloud Firestore, project `notes-f36b3`. There is no local database; offline support comes from Firestore's built-in cache.

Deep-link onboarding keeps its data elsewhere:

| Data | Where |
|------|-------|
| Stage, form details, chosen plan | On the device, in `shared_preferences` |
| Form details (name, email, phone, address) | Also inserted into the Supabase table `onboarding_leads`, insert-only for the app |

The table definition and its policy are in [09-deep-link-onboarding.md](09-deep-link-onboarding.md#saving-the-details).

## Schema

There is one collection:

```
users/{uid}/notes/{noteId}
```

| Field | Type | Constraint |
|-------|------|------------|
| `title` | string | At most 200 characters. May be empty. |
| `body` | string | At most 20,000 characters. May be empty. |
| `createdAt` | timestamp | Set by the server on create. Cannot change afterwards. |
| `updatedAt` | timestamp | Set by the server on every create and update. |

- The document ID is auto-generated by Firestore.
- There is no `ownerId` field. Ownership is the `{uid}` segment of the path.
- The `users/{uid}` document itself is never written. Only the subcollection exists.
- A document must contain exactly these four fields. The rules reject any extra or missing field.

## The `Note` model

[note.dart](../lib/models/note.dart) maps a document to an immutable `Note`.

| Member | Meaning |
|--------|---------|
| `id`, `title`, `body` | From the document. Missing strings become `''`. |
| `createdAt`, `updatedAt` | `DateTime?`. Null while a server timestamp is unresolved, which lasts roughly 100–300 ms after a write, or until reconnect when offline. |
| `isPending` | `metadata.hasPendingWrites`: written locally, not yet acknowledged by the server. |
| `sortKey` | `updatedAt`, or the current time when it is null, so pending notes sort to the top. |
| `displayTitle` | The title, else the first line of the body, else "Untitled note". |

The timestamps are nullable because `cloud_firestore` offers no way to request a local estimate for a pending server timestamp.

## Operations

All in [notes_repository.dart](../lib/services/notes_repository.dart).

| Method | Firestore call | Notes |
|--------|----------------|-------|
| `watchNotes(uid)` | `orderBy('updatedAt', descending: true).snapshots()` | Re-sorted on the client by `sortKey`. No pagination: the whole collection is loaded. |
| `create(uid, title, body)` | `doc().set(...)` | Both timestamps are `FieldValue.serverTimestamp()`. |
| `update(uid, id, title, body)` | `doc(id).update(...)` | Sends `title`, `body`, `updatedAt`. `createdAt` is left out on purpose. |
| `delete(uid, id)` | `doc(id).delete()` | Hard delete. No tombstone. |
| `restore(uid, note)` | `doc(note.id).set(...)` | Used by Undo. Counts as a create, so `createdAt` is re-stamped. |

The query needs no composite index. Firestore's automatic single-field index on `updatedAt` serves it, so there is no `firestore.indexes.json`.

## Security rules

[firestore.rules](../firestore.rules) is the source of truth. In summary:

| Operation | Allowed when |
|-----------|--------------|
| read | The signed-in user's ID equals `{uid}` in the path |
| create | Owner, valid note, and `createdAt` and `updatedAt` both equal the request time |
| update | Owner, valid note, `createdAt` unchanged, `updatedAt` equals the request time |
| delete | Owner |
| anything else | Denied |

"Valid note" means exactly the four fields, with the types and size limits in the schema table.

Two consequences for client code:

- **Timestamps must be `FieldValue.serverTimestamp()`.** A client-side `DateTime.now()` is rejected with `permission-denied`. This is what makes ordering trustworthy across devices with wrong clocks.
- **Adding a field needs a rules change first.** A write that includes a field the rules do not list is rejected.

## Publishing rules

The Firebase CLI is not installed and there is no `firebase.json`. Rules are published by pasting [firestore.rules](../firestore.rules) into Firebase Console → Firestore Database → Rules → Publish.

The file in this repository is not guaranteed to match what is live. After changing it, publish it and record that in the task log.
